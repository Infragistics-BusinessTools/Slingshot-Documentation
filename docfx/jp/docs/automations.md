# 自動化

自動化を使用すると、Slingshot が繰り返し発生する作業を代わりに処理します。たとえば、「タスクの期限が過ぎたら担当者に通知する」といったルールを 1 回設定すると、その条件が満たされるたびに Slingshot が実行します。自動化では、フィールドの更新、タスクの移動、コメントの投稿、通知の送信、タスク テンプレートの適用、時間の記録、会議の文字起こしからのタスク作成を行えます。

各自動化は、次の 3 つの要素で構成されるシンプルなルールです。

- **When**: 自動化を開始するイベントである _トリガー_ です (例: _タスクが作成されたとき_、_ステータスが変更されたとき_)。
- **If** _(オプション)_: 自動化を適用するタスクを絞り込む _条件_ です (例: _優先度が高いタスクのみ_)。
- **Then**: Slingshot が実行する 1 つ以上の _アクション_ です (例: _担当者を設定する_、_通知を送信する_)。

自動化を作成すると、Slingshot は「タスクの期限が過ぎたとき、優先度が高ければ、通知を送信する」のように、わかりやすい自然言語の概要を表示します。

> [!NOTE]
> ワークスペースで自動化を作成または編集するには、そのワークスペースの編集権限が必要です。ほかのワークスペース メンバーも自動化を開いて仕組みを確認できますが、変更はできません。

## 自動化の場所

メイン ナビゲーションから **Automations** を開きます。ページには、自動化が保存されている場所ごとに分類された一覧が表示されます。

- **My Automations**: 自分のタスクや会議で実行される個人用の自動化です。[会議の自動化](#会議の自動化)はここでのみ作成できます。
- **All Automations**: アクセス権のあるすべてのワークスペースの自動化です。ワークスペース ピッカーを使用して一覧を絞り込めます。
- **ワークスペースごとに 1 行**: そのワークスペースのタスクで実行される自動化です。ワークスペース行をドラッグして順序を変更できます。

ページ上部のサマリー タイルには、**Active** の自動化数、**今月** の実行回数、**合計** が表示されます。**Hide Paused** をオンにすると、有効になっている自動化のみが表示されます。

## 自動化を作成する方法

### 手順 1: 新しい自動化を開始する

**New Automation** をクリックまたはタップします。開始方法は 3 つあります。

- **Describe it**: 「タスクが Done に移動したら、期限をクリアして所有者に通知する」のように、何をいつ行うかを入力すると、Slingshot AI が確認用の自動化を作成します。
- **Use a template**: 以下の既製スターター テンプレートから選択します。ほとんどのテンプレートでは、1 つの設定 (たとえばステータスや担当者) を選ぶ必要があるため、入力するまで **Create** は無効のままです。
- **Start from scratch**: 空の自動化を開きます。

| テンプレート | 内容 |
|---|---|
| **新しい作業を既定の担当者に割り当てる** | 新しいタスクが作成されたときに、1 人がそのタスクを担当します |
| **作業の準備ができたらレビュー担当に引き渡す** | 選択したステータスに達すると、レビュー担当者に引き継がれます |
| **タスク タイプ別に新しい作業を振り分ける** | あるタイプの新しいタスクが作成されたときに、適切な担当者に割り当てます。名前付きのタスク タイプがワークスペースにある場合にのみ表示されます |
| **作業が移動したらコメントする** | タスクが指定した場所に移動すると、コメントが投稿されます |
| **期限切れの作業を通知する** | タスクの期限を過ぎると、担当者に通知します |
| **期限前に警告する** | 期日が近づくと、担当者に通知します |
| **ブロックされた作業をエスカレーションする** | 選択したステータスに達すると、優先度が上がり、誰かに通知されます |
| **受け付け時に既定の説明を設定する** | 新しいタスクが、入力した説明付きで開始されます |
| **サブタスクの完了時に親タスクを完了する** | すべてのサブタスクが完了すると、親タスクも完了します |

### 手順 2: 名前を付けて実行場所を選ぶ

Slingshot は設定内容に基づいて名前 (例: 「Task created → Set status」) を自動入力し、自分で入力するまで最新の内容に合わせて更新します。**Generate Name** をクリックまたはタップすると、Slingshot AI がより説明的な名前を作成します。

次に、**workspace** と自動化の適用範囲を選択します。ワークスペース全体に適用することも、特定のプロジェクト、リスト、またはセクションに限定することもできます。**My Automations** の自動化は個人のタスクに適用されます。

> [!IMPORTANT]
> 自動化の場所を変更すると、設定済みのトリガー、条件、アクションはクリアされます。使用できるフィールドは実行場所によって変わるためです。最初に場所を選択してください。

### 手順 3: トリガー (When) を選ぶ

新しい自動化では、既定で **Task created** が選択されています。別のトリガーを選ぶには、そのトリガーをクリックまたはタップします。トリガーはカテゴリごとに整理されています。

| トリガー | 実行されるタイミング |
|---|---|
| **Task created** | 自動化の対象場所でタスクが作成されたとき |
| **Task moved** | 指定したリストまたはセクションにタスクが移動したとき (またはそこから移動したとき)。サブタスクは親タスクと一緒に移動するため、各サブタスクに対してもアクションが実行されます |
| **Date arrives** | 日付に到達したとき。対象には、タスクの _Start Date_、_Due Date_、カスタムの _Date_ フィールド、または選択した特定のカレンダー日付が含まれます。また、その日付の前後に設定した時間で実行することもできます |
| **Date passed** | 選択した日付が過ぎて 1 日後 |
| **Task is overdue** | 期限日を 1 日過ぎても、タスクがまだ完了していないとき |
| **Start date has passed** | 開始日を 1 日過ぎても、タスクがまだ開始されていないとき |
| **Subtasks are complete** | タスクの直接のサブタスクがすべて完了したとき。アクションは **親** タスクに対して実行されます |
| **Title changed**、**Description changed**、**Status changed**、**Priority changed**、**Assignee changed** | タスク上のそのフィールドが変更されたとき |
| **Field changed** | 選択したカスタム フィールドが変更されたとき |

**Status changed**、**Priority changed**、その他のフィールド トリガーでは、あらゆる変更で実行するか、フィールドがある値 **に** 変わったときのみ、ある値 **から** 変わったときのみ、またはある値 **から** 別の値 **へ** 変わったときのみ実行するかを選べます。_Assignee_ などのユーザー フィールドでは、誰かが **追加** または **削除** されたときに実行できます。

> [!IMPORTANT]
> **Slingshot Tip**: **Date passed** はタスクが完了しているかどうかを確認しないため、完了済みのタスクでも実行されます。未完了の作業に対してのみ実行したい場合は、代わりに **Task is overdue** を使用するか、_Status_ 条件を追加してください。

#### トリガーとアクションで使用できるカスタム フィールド

**Field changed** トリガーと **Change field** アクションでは、次のカスタム フィールド タイプを使用できます。

| フィールド タイプ | トリガーとして | アクションとして |
|---|---|---|
| **Dropdown** | 任意の変更、特定の値への変更、特定の値からの変更、または値から値への変更 | オプションを設定、またはクリア |
| **People** | ユーザーが追加または削除されたとき | ユーザーを設定 |
| **Numeric** | 新しい値を比較: 次と等しい、次より大きい、次より小さい、など、または未設定 | 数値を設定、またはクリア |
| **Manual Progress** | 新しい割合を比較 | 割合を設定 |
| **Checkbox** | チェック済みまたは未チェック | チェックまたはチェック解除 |
| **Date** | **Date arrives** で使用 | 日付を設定、クリア、または計算 (以下を参照) |

_Date Range_、_Rating_、_Formula_ フィールドは、トリガーまたはアクションでは使用できません。

### 手順 4: 条件 (If) を追加する

条件はオプションです。**+ Condition** をクリックまたはタップしてルールのブロックを追加すると、その条件に一致するタスクに対してのみ自動化が実行されます。ブロック内で別のルールを追加するには、**+ Rule** をクリックまたはタップします。

各ルールでは、フィールドと値を比較します。たとえば、_Priority_ **is** _High_ のように設定します。条件には、_Status_、_Priority_、_Task Type_、_Title_、_Description_、日付、ユーザー、多くのカスタム フィールド、およびタスクの **Project** または **List** を使用できます。タスクがセクション内にある場合も含め、そのプロジェクトやリスト内のどこかに存在していれば、「そのプロジェクトまたはリストにある」と見なされます。

最初のルール以降は、各ルールが **And** または **Or** で結合されます。切り替えるには、コネクタをクリックまたはタップします。ルールは上から順に読み取られるため、「A **And** B **Or** C」は「(A and B) or C」を意味します。

> [!NOTE]
> **Status changed** や **Date arrives** のように、トリガーで場所を選べない場合は、**Project** または **List** 条件を使用してください。例: ステータスが _Done_ に変わったとき、タスクが _Launch_ リストにある場合は、_Shipped_ セクションに移動します。

### 手順 5: アクション (Then) を追加する

最初のアクションは **Set status** で始まるため、値を選ぶだけで使用できます。別のアクションに変更することもできます。さらに追加するには **+ Action** をクリックまたはタップします。1 つの自動化に追加できるアクションは最大 **20** 個で、順番に実行されます。

| アクション | 内容 |
|---|---|
| **Mark subtasks complete** | タスクの未完了の直接サブタスクをすべて完了としてマークします |
| **Move task** | タスクを同じワークスペース内の別のセクションまたはリストに移動します |
| **Apply template** | 保存済みのタスク テンプレートを、タスク自身のセクション、または選択した場所に適用します |
| **Set title** | タスクのタイトルを置き換えます。タイトルを空白にはできません |
| **Set description** | タスクの説明を置き換えます。書式付きテキストやリンクは使用できますが、画像は使用できません |
| **Set status**、**Set priority**、**Set assignee**、**Set start date**、**Set due date** | タスク上のそのフィールドを設定します |
| **Change field** | カスタム フィールドを含む、その他の対応フィールドを設定またはクリアします |
| **Send notification** | 選択したユーザーに通知します (以下を参照) |
| **Create comment** | タスクにコメントを投稿します。テキストの書式設定や @メンションを使用できます |
| **Log time** | 選択したユーザーと時間で、タスクに時間エントリを記録します |

**日付アクション。** _Start Date_、_Due Date_、またはカスタムの _Date_ フィールドを設定するときは、特定の日付を設定する、クリアする、別の日付フィールドをコピーする、別の日付の前後に指定した日数を設定する、または自動化が実行された時点を基準に設定する (例: 「実行の 1 週間後」) ことができます。

> [!NOTE]
> 必須フィールドは自動化でクリアできません。

#### 通知を送信する

**Send notification** には 3 つの要素があります。

- **Recipients**: **Current Assignees**、タスクのカスタム _People_ フィールドに含まれるユーザー、または特定のワークスペース メンバーを選択します。
- **Subject Line** _(必須、最大 100 文字)_。
- **Message** _(オプション、最大 255 文字)_。

**Insert** ボタンを使用すると、通知送信時に Slingshot が値を埋め込むプレースホルダーを追加できます。使用できるのは **Task name**、**List**、**Workspace**、**Automation name** です。

受信者には、その人の通知設定 (**Automation notifications** を参照) に応じて、アプリ内通知、プッシュ通知、メールで通知されます。タスクを表示できないユーザーや、そのタスクをミュートしているユーザーには通知されません。

> [!NOTE]
> 文字数制限は、展開後の文字列ではなくプレースホルダー自体を数えます。タスク名が長い場合、配信される件名が 100 文字を超えることがあります。その場合は短縮されます。

#### タスクを移動する

**Move task** は、タスクのタイプを変更しません。リスト固有のタスク タイプを使用しているタスクはそのリスト内に留まるため、それらのタスクに対する別のリストへの移動はスキップされます。同じリスト内の別のセクションへの移動は常に成功します。

#### テンプレートを適用する

保存済みのタスク テンプレートを選択してから、**Apply to** で **Same location as the task** または **Choose location** を選択します。テンプレートの日付は、自動化が実行された日を基準に計算されます。

> [!IMPORTANT]
> 1 回の実行でテンプレートから作成できるタスクとサブタスクは最大 **300** 件です。より大きいテンプレートはスキップされ、実行履歴にその旨が表示されます。テンプレートによって作成されたタスクが別の **Apply template** を再び発生させることはないため、テンプレートが連鎖して積み重なることはありません。その他の自動化は引き続き実行されます。

#### 時間を記録する

**Log time** は、自動化が実行されるたびに時間エントリを追加します。同じタスクでトリガーが複数回発生する可能性がある場合、時間は実行ごとに加算されます。

### 手順 6: 保存する

**Create** (または編集時は **Update**) をクリックまたはタップします。自動化に名前、トリガー、および完全な一連のアクションが設定されると、ボタンが有効になります。設定が不足している場合、Slingshot は対応が必要な箇所を強調表示します。

新しい自動化は、作成するとすぐにオンになります。

## 会議の自動化

自動化はカレンダーでも実行できます。**My Automations** で自動化を作成し、**When** セクションで **Runs on** を **Task** から **Calendar event** に切り替えると、会議トリガーを使用できます。切り替えると、すでに設定していたトリガー、条件、アクションはクリアされます。

> [!IMPORTANT]
> 会議の自動化は **My Automations** でのみ作成できます。各自動化は作成者のカレンダーを監視するため、ワークスペースでは使用できません。**Runs on** が表示されない場合は、**My Automations** で自動化を作成していることを確認してください。

> [!NOTE]
> 会議の自動化は、接続された Microsoft カレンダー上の Microsoft Teams 会議で機能します。

**トリガー: Meeting transcript is available。** 会議の終了後、その文字起こしの準備ができると実行されます。1 つの会議または定期的なシリーズを選ぶには **Event or series** を、カレンダー上のすべての会議を対象にするには **All events** を選択します。

**条件。** 会議の _Title_ (含む、含まない、等しい、等しくない)、自分が主催者かどうか、または主催者が誰かによって、会議の自動化を絞り込めます。

**アクション:**

- **Create tasks from action items**: Slingshot が文字起こしを読み取り、アクション アイテムを見つけて、選択したセクションまたはリストに各項目のタスクを作成します。**Assign to** では、**The attendee named in the transcript**、**Me**、**No one** のいずれかを選択します。タスクは、会議ごと・保存先ごとに 1 回だけ作成されます。
- **Post summary to discussion**: 会議の AI 要約を選択したディスカッションに投稿します。そのディスカッションで編集権限が必要です。

> [!IMPORTANT]
> **Slingshot Tip**: 「この会議のアクション アイテムをタスクに変換する」をすばやく設定するには、カレンダー上の会議に表示される **Turn action items into tasks** のヒントを見つけて、**Set it up** をクリックまたはタップします。

## 自動化を管理する

一覧で自動化をクリックまたはタップすると開きます。パネルには 2 つのタブがあります。自動化を編集する **Details** と、**Run History** です。

- **オンまたはオフにする**: 自動化のスイッチを使用すると、設定や履歴を失わずに一時停止できます。一時停止した自動化は実行されません。
- **複製**: オーバーフロー メニューから自動化をコピーし、類似する自動化の出発点として使用できます。
- **削除**: 自動化を完全に削除します。この操作は元に戻せないため、再度必要になる可能性がある場合は、代わりにオフにしてください。

### 実行履歴

**Run History** には、自動化が実行されたすべての履歴が新しい順に日ごとにグループ化されて表示されます。**Run History** タブ、自動化のオーバーフロー メニュー、または一覧内の実行回数をクリックまたはタップして開くことができます。各実行には、次の内容が表示されます。

- **実行対象のタスク**。
- **各アクションの実行内容**。たとえば「Set Status to In Progress」や、変更するものがなかった場合の「Already set to In Progress」などです。
- **実行場所と実行のきっかけ**: リスト (クリックまたはタップして開く) と、その実行を引き起こしたユーザー、または **Triggered by another automation**。

何も変更しなかった実行は、その理由とともにスキップとして表示されます。完了できなかった実行は、失敗としてマークされます。

### 構成エラー

カスタム フィールド、タスク テンプレート、プロジェクト、リストなど、自動化が依存しているものが削除されると、その自動化は一覧でエラーとしてマークされます。開くと、対応が必要な設定が赤で強調表示されます。修正または置き換えるまで保存できません。

> [!NOTE]
> 自動化のトリガーが参照しているリストまたはセクションを削除すると、Slingshot はその自動化をオフにします。

## 知っておくと便利なこと

- **変更を行う主体。** 自動化による変更、コメント、通知は、タスクのアクティビティに **Automations (_自動化名_)** として表示されるため、どのルールが何を行ったのかが常に明確です。
- **アクションは順番に実行されます。** 1 つのアクションが完了できなくても、他のアクションは引き続き実行されます。
- **自動化同士をトリガーできます。** たとえば、ある自動化がステータスを設定し、別の自動化がそのステータス変更に反応できます。自動化が自分自身を再トリガーすることはありません。また、Slingshot は自動化の連鎖を 8 段階で停止します。停止した実行は Run History に赤で表示されます。
- **適切な場所から値を選択してください。** Dropdown オプションは特定のタスク タイプに属します。自動化がタスクのタイプに存在しないオプションを設定しようとすると、そのアクションはスキップされます。
- **日付トリガーと既存のタスク。** _Start Date_、_Due Date_、またはカスタム日付フィールドに対する **Date arrives** は、タスクが作成または更新されたときにスケジュールされます。特定のカレンダー日付に対する **Date arrives** は、その日付になった時点で対象範囲内のすべてのタスクを 1 回確認します。

## 自動化で Slingshot AI を使用する

[Slingshot AI](slingshot-ai-overview.md) とチャットすることでも、自動化を管理できます。自動化の作成 (「優先度の高いタスクの期限が過ぎたら通知して」)、既存の自動化の説明、変更、オン / オフの切り替え、削除を依頼できます。Slingshot AI は、何かを作成または変更する前に確認カードを表示します。

## ヒント

- **テンプレートから始める。** スターター テンプレートは最も一般的なルールをカバーしており、チーム固有の内容だけを入力すれば使えます。
- **適用範囲を絞る。** 必要なプロジェクトやリストにだけ自動化を適用するか、**Project** または **List** 条件を追加し、どこでも実行される状態を避けてください。
- **日付トリガーには Status 条件を追加する。** 作業が完了したらリマインダーが止まるようにします。
- **新しい自動化を設定したら Run History を確認する。** 期待どおりに動作したことを確認できます。
